# Stage 28 — independent SD-reloadable terrain atlas

This stage changes the **ROM-free Switch graphical diagnostic**, not the
original Vice: Project Doom level. The ground tiles are new synthetic artwork.

## New architecture

- The embedded environment atlas has four separately drawn 16x16 RGBA frames.
  It is generated by tools/build_demo_terrain.py without original NES files.
- Existing collision data from game_core are unchanged.
- The ground renderer samples neighboring solid tiles for a variant:
  top A/B, left exposed wall, or right wall; interiors use masonry.
- The environment is loaded by graphics_core/terrain_source.cpp, independent
  of the hero's VPAT+VANM texture/animation bundle.
- A valid external replacement updates the image without changing collision,
  gameplay timing, hero poses or the existing scene/parallax code.
- Invalid files, bad checksums, wrong frame counts and unsupported square
  geometry do not replace the last accepted terrain atlas.

## SD card layout

Place any newly authored terrain at:

    sdmc:/switch/vice_project_doom/terrain.vpat

    switch/
      vice_project_doom/
        vpd_native_scene.nro
        hero.vpat        optional; independent character artwork
        hero.vanm        optional; independent character timing
        terrain.vpat     optional; independent stage-28 environment

Controls remain compatible with earlier builds:

| Input | Action |
|---|---|
| X | Reload hero atlas + optional animation resource together |
| Y | Reset hero art and timing |
| ZL | Reload terrain.vpat only |
| ZR | Reset terrain to embedded artwork |
| D-pad / left stick | Move in the invented test scene |
| A / B | Jump |
| Plus | Exit |

The onscreen HUD reports TERRAIN: SD, TERRAIN: EMBEDDED, or TERRAIN: FAILED.
A failed ZL reload preserves the preceding valid ground tiles. Loading
terrain and loading hero resources are intentionally separate operations;
there is **no atomic promise across unrelated asset groups**.

## Tile atlas contract

The resource uses the existing VPAT v1 little-endian RGBA8888 format
and checksum. Four frame IDs are required: 0 = exposed top A, 1 =
top B or interior, 2 = left wall edge, 3 = right wall edge.

For accurate 32x32 screen-cell compositing, each frame must be square
and **4, 8, 16 or 32 pixels** across, scaling by 8x, 4x, 2x or 1x.
Any other dimensions are refused before becoming active.

Import a newly drawn four-frame, 128x32 sheet (each frame 32x32):

    python3 tools/pack_vpat.py private/terrain_sheet.png \
      --frame-width 32 --frame-height 32 --frames 4 \
      --binary private/terrain.vpat

Then copy the generated VPAT to the SD path and press ZL.

To recreate the original synthetic *embedded* VPAT (no PNG library
needed in the devkitPro build container):

    python3 tools/build_demo_terrain.py private/demo_terrain.hpp \
      --raw private/demo_terrain.vpat \
      --preview private/demo_terrain.ppm

The source is deliberately generated by code and is not a remastered
or extracted original first-stage texture.

## Verified / not yet verified

The ROM-free host tests verify four generated patterns, VPAT CRC,
geometry constraints, four tile selection cases, framebuffer changes
when loading new art, failed reload rollback and restoring embedded
art. The shared C++ sources are also compiled into a libnx NRO by
the native graphical GitHub Actions workflow.

No physical Nintendo Switch has been used to verify the new rendering
or SD-card behavior. GPU/CPU frame times remain unmeasured. Neither the
original level layout nor authentic timing and palette data have been
reconstructed. See ROADMAP.md for unresolved M1 research.
