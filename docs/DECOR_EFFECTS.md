# Stage 30 — independent animated decorations and simple effects

Stage 30 adds **ROM-free, independently authored decorative objects** to
the native Nintendo Switch graphical *diagnostic*. These are visual objects
only. This is not a reconstruction of Vice: Project Doom's original map,
effects, or level scripting.

## What is drawn

The project creates one VPAT v1 alpha atlas containing four cells:

| Frame | Test object |
|---:|---|
| 0 | Industrial signal lamp, bright |
| 1 | The same lamp, dim |
| 2 | Air fan, blade pose A |
| 3 | Air fan, blade pose B |

The original example is generated by
[build_demo_decor.py](../tools/build_demo_decor.py), using only Python
drawing instructions, without the commercial game data.

The [decoration source](../graphics_core/decor_source.cpp) selects props
using **fixed world coordinates** and the current fixed-step simulation
tick. Even-indexed objects are lamps behind terrain and the hero;
odd-indexed objects are fans in front of the hero but behind the HUD.
The two object groups intentionally have different animation periods:
lamps alternate every 24 ticks, fans every 9 ticks.

World positions are authored **test scene constants** with 176 world pixels
between objects. They are not recovered from an NES stage. World-to-screen
mapping honors camera scrolling. No objects have physics bodies or collision
events. They cannot change level topology or player movement.

Order of visible drawing:

1. Sky gradient, moon, stars and two parallax skyline layers.
2. Rear lamps (alpha composited).
3. Solid, collision-backed terrain tiles.
4. Hero sprite.
5. Foreground fans (alpha composited).
6. HUD and diagnostics.

The 4-frame atlas may have source cell sizes **12×16**, **24×32**,
or **48×64** pixels; all map to a fixed 48×64 on-screen prop at 4×,
2× or 1×. Other dimensions are rejected before resource activation.
The original built-in developer atlas uses 24×32 cells and 2× scale.
Each pixel uses VPAT straight-alpha RGBA and existing clipping.

## Replace decorations on the SD card

Copy your own independently painted, 4-frame VPAT to:

    sdmc:/switch/vice_project_doom/decor.vpat

An SD layout for the latest diagnostic NRO looks like:

    switch/
      vice_project_doom/
        vpd_native_scene.nro
        hero.vpat         optional
        hero.vanm         optional
        terrain.vpat      optional
        backdrop.vpat     optional
        decor.vpat        optional

Controls:

| Control | Result |
|---|---|
| D-pad **Up** | Reload decor.vpat (only the decorations) |
| D-pad **Down** | Restore embedded decorations |
| L / R | Reload / restore the parallax background |
| ZL / ZR | Reload / restore terrain |
| X / Y | Reload / restore hero and animation |
| Left / right | Move the test character |
| A / B | Jump |
| Plus | Exit |

The HUD reports **DECOR: SD**, **DECOR: EMBEDDED** or **DECOR: FAILED**.
If the external file is missing or invalid, the last accepted decoration
atlas remains intact; the built-in test art always works.

As with terrain and backdrop sources, this is **not** an atomic update
across unrelated resource groups: only the decoration atlas is replaced
by the Up action. No external files are edited by the runtime.

## Import four independently authored object frames

For an original 192×64 RGBA PNG with four 48×64 sprite frames:

~~~sh
python3 tools/pack_vpat.py private/decor_sheet.png \
    --frame-width 48 --frame-height 64 --frames 4 \
    --binary private/decor.vpat
~~~

The resource is accepted only after VPAT v1 header/length/CRC checks,
correct four-frame count, and a supported cell aspect ratio/size. CRC32
detects accidental file corruption, **not** tampering or license status.

To reproduce the embedded artwork for reference:

~~~sh
python3 tools/build_demo_decor.py private/generated/decor.hpp \
    --raw private/generated/decor.vpat \
    --preview private/generated/decor.ppm
~~~

## Automated checks and limitations

Synthetic C++ and Python tests verify frame differences, alpha,
deterministic animation timing, world scrolling, separate back/foreground
compositing, invalid file rejection, geometry validation and retaining
the last valid resource. GitHub Actions cross-compiles the *same* code
into a native libnx NRO and publishes a diagnostic artifact.

All game map positions and object timing values remain independently
invented. The project has **not** measured original level effects or
created production HD character/scene art. The NRO is built by CI, but
the decorations have not been run or profiled on physical Switch hardware.
