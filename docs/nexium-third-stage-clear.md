# NeXium stage: third live attempt earns full stage completion

This phase extends the prior PR #34, which witnesses the third attempt's
true first-guard defeat after original earned victory -> first Minus ->
real five-hit defeat -> second Minus.

## Scenario and proof

1. NeXium actually presses **D=Right** after the restored first guard's
   final source-swept projectile hit, and waits for a brand-new third-run
   wave activation recorded by the same rendered guest Simulation.
2. The new guest witness requires a dead three-hit first guard,
   second wave active, a live player and an untouched two-HP sentry
   while the actual right-movement input is consumed.
3. The host holds **D+Z** (Right+Fire) until the same Simulation
   registers two swept hits on the second-wave sentry and authentic
   stage completion at the exit.
4. The native journal must contain exactly two events, wave -> exit.
   Both are tied to the third attempt: the prior independent
   source-defeat record and its actual X11 confirmation are mandatory.
5. NeXium captures another real 1280x720 X11 raster after the final
   third-run exit. An independent audit requires source states, host
   input and changed central framebuffer pixels. Host logs alone,
   offscreen scripts or C++ fixture simulations cannot pass this audit.

A separate portable C++ full-cycle simulation and Python mutation
fixtures check the same serializer and reject forged order, enemy HP,
shots, time, input or progression.

The entire gameplay map, graphics and opponents are self-authored
**ROM-free placeholders**. NeXium proof does not mean the original NES
engine, stage rules or assets were recovered and does not measure
physical Nintendo Switch performance.
